# Invite-only onboarding

The system operator creates a business and its initial ADMIN invitation through `node --import tsx scripts/tenant-operator.ts create <name> <admin-email> <private-output-file>`. Operator shell access is required; no business-creation HTTP endpoint is exposed. `APP_URL`, the restricted `DATABASE_URL` and `TENANT_ENFORCEMENT=true` are required. The link is written to a new mode-600 file and must be handed to the intended recipient privately. No email is sent. A new business has no customers, catalog or orders; only its own store configuration (automatic purchasing disabled).

Business admins use `/settings/users` to create ADMIN / OPERATIONS invitations, copy the link, revoke an invitation or revoke membership. Links contain 256 random bits, expire after 48 hours and are stored only as SHA-256 hashes. Acceptance locks the invitation row and marks it used atomically with membership creation. Expired, revoked and consumed links cannot be reused. The final active admin cannot be removed, including concurrent removals.

`/invite#<token>` keeps the token out of server URL/referrer logs and removes the fragment from browser history after reading it. A new account chooses a 12+ character password. An existing global account must authenticate with its current password; acceptance does not change its identity, password or memberships in other businesses. An operator can recover an account with `RECOVERY_PASSWORD=<provided securely> node --import tsx scripts/tenant-operator.ts recover <email>` after verifying the person's identity. Recovery increments session_version and invalidates existing JWTs. Business admins cannot perform global password resets. No external recovery message is sent.

The active-business selector lists verified current memberships. Switching mints a new signed session only after a fresh membership lookup, clears local drafts/storage and reloads the application. Other tabs reload on token changes. Login also clears previous-account browser storage. Server responses containing business data disable shared caching. The selector warns before discarding unsaved drafts.

## Verification and limits

The local PostgreSQL integration script `scripts/verify-tenant-invitations.ts` passed 14 checks: empty business; hash-only storage; exactly one successful concurrent acceptance; tenant/role binding; forbidden staff invitations and foreign revocations; session invalidation on membership removal; expired/revoked links; protection of existing global credentials; different roles for a shared user; recovery session revocation; retention of the last admin under concurrent removal; and a shared pre-authentication rate limit across independent limiter instances.

The new invitation and team screens were exercised against both the development server and the production build on localhost at 390/768/1440 pixels, with no horizontal overflow or browser runtime errors. Actual HTTP checks covered acceptance, admin-only invitations, revocation against an existing cookie, forged selection and switching with draft cleanup. Keyboard forward/reverse focus order and RTL were checked on the invitation form. The remaining core screens and the complete historical unit suite are still required. No real invitations, recovery actions, business provisioning or external messages were performed. The migration only adds a session-version column and updates the reference trigger so revoking an assigned worker does not prevent unrelated updates to old records.

The active session implementation uses AUTH_JWT_SECRET. Unused legacy JWT keys are optional at boot; the legacy validator still requires them if explicitly instantiated. An actual browser boot caught and removed the obsolete mandatory-key requirement. Production still rejects a missing active signing key.

The script refuses remote hosts and exercises only synthetic accounts. The API test run passed eight scenario groups with no browser runtime errors. Full TypeScript, production build, ESLint (three pre-existing warnings), 33 focused unit checks and the 764-key translation checker passed.
